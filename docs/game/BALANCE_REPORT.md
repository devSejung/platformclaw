# 낚시 경제 검증

최종 계약은 40종 단일 풀의 수동 낚시다. 원래 기본값을10으로 나누어 성공 포획의
GOOD 기본 보상 평균 약15G를 목표로 한다. 각 포획이15G라는 보장은 아니다.
장력 전투 성공 뒤 왕복 바 정확도를 판정하고, 최종 포획 때 공통 G를 한 번 지급한다.
판매·자동·장비·지역 비용과 별도23초 대기시간은 없다.

## 정본과 보상

`packages/platformclaw-control-plane/src/data/economy/fishing.json`이40종 가중치,
기본값과 개별 기본 난도를 소유한다. 확률은 가중치 합40,000으로 정규화한다.
최종 기본값의 수학적 가중 평균은15.4905G다. 최종 표본 실측은 아직 대기 중이다.
서버는 정규화된 크기 표본`t`와
챔질의 정수 백분율`q`(GOOD100/PERFECT110)로 다음 정수 quote를 만든다.

```text
baseGold = max(1, round(basePrice × (85 + 30 × t) × q / 10000))
rewardGold = round(baseGold × (1 + finishAccuracy))
```

마무리 정확도는0–1, 보너스는1–2배다. 마무리4초가 지나면 기본1배를 자동 지급한다.
전투 성공만으로 먼저 G를 지급하지 않는다. 전투의 줄끊김·늘어짐·시간 초과는
실패이므로 무보상이며, 이미 이긴 뒤 마무리 제한시간 만료와 구별한다.

## 크기와 전투

실제40종×최소/중간/최대 크기×100시드의12,000전투를 실행했다. 제어 정책은
12,000승/실패0, 계속 누르기와 무입력은 각각0승이었다. 이는 순수 재생의
스크립트 정책 결과이며 실제 사용자의 성공률이나 최종 저장소 지급 증거가 아니다.

`resolveFishingDifficulty(fishId, lengthCm)`는 종의 기본 난도와 개체 크기를
정수1–10 난도로 합친다. 붕어의 크기0/.5/1에서는 난도1/3/5와 전투시간 중앙값
4216.67/5383.33/5533.33ms를 관찰했다. 현재 계약은 종·길이·희귀도를 포획까지
숨기며 중립 그림자를 쓴다. 행동/해결 난도만 챔질 뒤 물리 재생에 공개하고,
최종 결과의 길이가 잡힌 물고기의 시각 크기를 결정한다.

## 공통 경제와 보존

`SqliteGameEconomy`가 공통 지갑과 원장을 소유한다. 야구의 최종 보상은 안타5G,
홈런8G, 매3연속 홈런+10G와 매누적5홈런+10G다. 두 보너스는 중첩하므로15연속째가
누적15번째면8+10+10=28G다. 기존 지급 내역은 다시 계산하지 않는다.
경마의 기존3% 배당 공제와 기존 구매 가격은 유지한다. 낚시 입장500G는 지급하지 않는다.

모든 어종이 첫 판부터 가능하여 낚시 G를 야구 장비나 경마에 쓸 수 있다.
최종 보상·포획/기록·원장은 한 거래로 한 번 반영한다. 서버 전용 `rewardQuote`는
begin 때 GOOD/PERFECT 기본 금액을 고정한다. 이후 가격표 변경은 새 판부터
적용하고 진행 중 판·기존 G·기록·immutable receipt는 다시 계산하지 않는다.

과거 자동 상태/미판매 포획은 데이터베이스의 일회성 변환 소유자가 처리한다.
재접속·중복 finish/settle·여러 탭·재기동에서도 중복 지급과 클라이언트 시각 판정을
허용하지 않는다. 저장소와 실제 브라우저 증거는 [구현 보고서](/game/IMPLEMENTATION_REPORT)에서 확인한다.

이전/25 표본 GOOD6.3147625G와/20 GOOD7.8333325G는 역사적 중간판 결과이며
현재 수익으로 재사용하지 않는다. 해당 데이터는 ignored proof artifacts에 보존한다.
